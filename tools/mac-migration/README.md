# BIG TUNA Mac migration kit

This unsigned local kit installs Node 24, Git, Cloudflare Tunnel, Google Chrome and PM2 on an Apple Silicon Mac. It first runs a localhost preview. It never activates a preliminary snapshot. Keep the Windows computer intact until the final cutover and reboot checks succeed.

Runtime configuration is restored privately from allowlisted saved Windows PM2 settings, then captured app environment, then `server.env` with the highest priority. This preserves API credentials and assignment action secrets that lived outside `server.env`; the existing MCP token file is retained. Environment files are parsed as data, never executed as shell code. Windows CPU overrides and stale HomeKit IP addresses are removed from the translated launch settings, while originals remain in the private generation.

1. Transfer this entire folder plus the encrypted `.btm` bundle to the Mac. The separate recovery key stays outside the kit. Extract the zip into your Downloads folder. If executable bits were lost, in Terminal run `chmod +x ~/Downloads/BigTuna-Mac-Kit/*.command` (adjust the actual folder name).
2. In Finder open `Setup.command`. If macOS blocks this unsigned script, use System Settings → Privacy & Security → Open Anyway for this specific script, then confirm. Never disable Gatekeeper globally. Homebrew asks for your Mac administrator password; finish Apple's Command Line Tools prompt and rerun Setup if requested.
3. Select the encrypted bundle in the file chooser, then paste the hidden recovery key. Use `networksetup -listallhardwareports` in Terminal to identify the Ethernet `enN` interface. Each restore creates a new folder below `~/BigTuna/generations`; it never overwrites an earlier copy. A failed attempt leaves the fresh generation for inspection, while the previous one is preserved. Rerun Setup/Restore after fixing the reported error.
4. Run `Verify.command`. In the localhost site verify account login, saved records and every essential app. Preview has no tunnel, HomeKit or scheduled jobs. User actions can still call external APIs; avoid email sending/device controls in preview. Brightspace Google Chrome profiles are retained but Windows sessions may need fresh login; approve Google Chrome in macOS Privacy & Security when needed. Original Windows configuration and Git work remain preserved.
5. For final cutover follow the main migration guide on Windows: stop **all writers**, create the `--final` export, transfer it and run `Restore.command` on the Mac. This restores a separate fresh generation, including `.git` and all unfinished changes. Do not do new app development inside preview before final restore without separately saving that work.
6. Keep Windows stopped. Open `Activate.command` and type `ACTIVATE` only when ready to switch public traffic. It checks the final snapshot label, starts production, registers a launchd boot service running as your Mac account, and enables Cloudflare. A Mac administrator password is required. Scheduled jobs/HomeKit run only now. SSH ingress is omitted from the Mac tunnel config; Remote Login/SSH requires deliberate macOS setup later.
7. Verify the public domain, native apps, lights and HomeKit on the real LAN. **Restart the Mac, unlock FileVault if asked, and run `Reboot-Check.command`.** It checks the launchd boot registration, complete saved PM2 production set, stable live processes, MCP authentication and Google Chrome. Also verify the public site from your phone while signed out of the Mac to prove it survives logout. The system launchd service automatically starts all configured web, MCP, Cloudflare and Ollama processes as your owner account without opening the kit or a Terminal window. Activate disables automatic system sleep and requests automatic restart after power failure where supported. Display sleep remains independent. FileVault can require owner unlock after reboot/power loss before the volume/services are available; launchd cannot bypass it. Keep Windows intact until actual reboot and device checks pass.

`Stop.command` stops Mac PM2/tunnel and removes its installed boot registration, so production stays stopped across reboot until you run Activate again. `Backup.command` requires you to close all editors, Codex chats, builds and other writers, stops Mac services, verifies each source before/after copying and again across the complete snapshot, then creates a private encrypted snapshot with a checked manifest in `~/BigTuna-Backups`. It leaves services persistently stopped. Store the recovery key separately, copy the encrypted backup to an external drive, then run Activate to resume final production. `Restore-Backup.command` decrypts and verifies a backup into a fresh generation, reinstalls dependencies, translates generation paths and launches preview. Verify that restored preview before activating it. Check backup readability before relying on it. Keys generated on the same Mac are only separate files until you move them to separate secure storage.

`Update.command` is optional and owner-operated: it refuses any dirty Git checkout or non-main branch, fetches then fast-forwards, installs dependencies, and leaves services stopped if any step fails. Migration's registry translations can make the server checkout dirty; review and preserve these changes before updating. There is no unattended auto-update job.

Install full Xcode separately from the Mac App Store, open it, accept its license/components, sign into your Apple account and select your team for each project. Sign into GitHub using your preferred app/CLI and reauthorize access. SSH/developer configuration is preserved inside the private generation; inspect it before copying narrowly into `~/.ssh` or `~/.config`, never overwrite existing Mac credentials blindly. Import signing certificates/profiles manually where needed; copied files do not establish Keychain trust or account sign-in. Native app projects remain under each generation's APPS folder.

On 256 GB storage keep 40–60 GB free for Xcode, simulators and builds, plus bundle size × 3 + 15 GB for restore/dependencies. Older generations consume extra disk; retain them until rollback is no longer needed. `Setup-Local-AI.command` optionally installs Ollama and the two existing Eco AI models (`llama3.1:8b` and `qwen2.5-coder:7b`) after an explicit prompt and space check. It manages Ollama with isolated PM2, preserving model names and removing Windows CPU overrides. Allow about 12 GB for those models and use one at a time on 16 GB RAM. No models are automatically downloaded by the main installer. Firmware/physical device and Apple signing checks require the actual Mac.

`Enable-SSH.command` restores your original Cloudflare SSH hostname only after you enable macOS Remote Login, restrict it to your owner account, review/install your authorized keys and confirm the prompt. It checks local port 22 and restarts the tunnel only if production is already active. Remote-login settings and key authentication need verification from your usual client. Repeat this deliberate enable step after restoring another generation.

Rollback after public writes needs data reconciliation: stop Mac writers, back up its newest data, and deliberately transfer/reconcile it before restarting Windows. Merely restarting Windows would lose Mac-side writes.

Installer choices follow [Homebrew installation](https://docs.brew.sh/Installation), [Google Chrome cask](https://formulae.brew.sh/cask/google-chrome) and [Puppeteer browser configuration](https://pptr.dev/api/puppeteer.configuration). Actual launchd, Google Chrome, Xcode and HomeKit execution must be tested on your Mac; Windows syntax/helper checks cannot establish physical success.
