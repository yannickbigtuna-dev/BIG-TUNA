# Mac mini migration implementation specification — 2026-10-14

## Outcome and boundary

Prepare a private, portable migration kit for the owner's 16 GB / 256 GB Mac mini on Ethernet. Preserve the Windows server and all pre-existing work. Do not switch public traffic, stop production, push main (which auto-deploys), publish secrets, or claim Mac-only checks were executed on Windows. Mac execution and the final consistent data snapshot/cutover are owner-operated steps. Keep the unrelated unfinished active plans intact; append only a pointer in active.md.

## Architecture and ownership

1. Runtime implementer owns pty-worker.js, mcp-server/server.js, new mcp-server/platform.js, server.js, and focused new platform tests. Use configurable roots and platform shells. Realpath containment must reject sibling-prefix, traversal and symlink escapes. Preserve Windows defaults. Add BIG_TUNA_STAGING=1 to suppress assignment/Strava/notification schedulers and HomeKit during Mac preview, without altering default production. Native identities/data/API contracts remain unchanged.
2. Export implementer owns scripts/migration/* and test/migration-export.test.js. Supply a Windows-friendly Node CLI and reusable crypto module. Snapshot full SERVER and APPS including .git, ignored production data/secrets and unfinished changes, Cloudflare credentials, narrowly enumerated developer configuration/SSH and external private release roots. Exclude rebuildable node_modules, caches, Windows binaries/drivers, logs and huge local model blobs; report every exclusion. Never follow links or lose linked Git worktree metadata silently. Output encrypted authenticated archive, checksum, nonsecret inventory and a separate locally generated recovery key. Fail rather than silently skipping unreadable/changing files. Default online export must be marked preliminary; final mode requires owner-confirmed stopped writers. Use crypto.scrypt + AES-256-GCM streaming with versioned header. Shared CLI: node scripts/migration/export.cjs --output <directory> [--final]; crypto CLI: node scripts/migration/crypto.cjs decrypt <bundle> <tar-output> with key through stdin. Bundle contents top-level SERVER/, APPS/, PRIVATE/, manifest.json; manifest records each path,size,sha256, source and exclusions, consistency status. Provide validation CLI for extracted manifest. Do not echo secrets. Self-tests use synthetic temporary roots and wrong-key/corruption cases.
3. Mac implementer owns tools/mac-migration/* and test/mac-migration.test.js. Build Finder executable Setup.command, Restore.command if needed, Verify.command, Activate.command, Stop.command, Backup.command and explicit owner instructions. First install supported Node/Git/compiler tooling, cloudflared, PM2, appropriate Chromium for Puppeteer on Apple silicon, optional Ollama (retain model names, remove forced Windows CPU backend). Consume encrypted bundle/manifest via shared Node helpers; verify authenticated decryption and safe archive listing before extraction, manifest hashes before restoring. Restore into fresh dedicated destination ~/BigTuna, refuse overwrite and report free-space constraints. Never source server.env as shell code. Translate actual path-valued config, app registry, Brightspace profile dirs, HomeKit Ethernet interface, cloudflared credential paths. Launch boot services with launchd under the owner, explicit executable paths, TZ=America/Halifax, staging first, no tunnel/schedulers/HomeKit until Activate. Fast-forward updater opt-in only, git safety and npm failure handling. No remote command/public exposure changes. Backups separate from public folders and include secrets with restrictive permissions. Reruns must be safe; logs redact secrets. Local .command kit is unsigned: clearly explain first-run Finder permission steps, never disable Gatekeeper globally. Full Xcode and Apple/GitHub account sign-in remain manual.
4. Root owns this spec, active plan pointer, CODEX_CONTEXT.md, docs/MAC-MIGRATION.md, integration corrections after delegation, review, comprehensive tests, final artifact assembly and private export. Preserve artifacts/ and backups/ already untracked. Artifact lives outside static apps; never upload it or put a decryption key into the downloadable kit.

## Threat model and operational constraints

Production data, keys, APNs secrets, OAuth tokens and HomeKit identities must move together without rotation. Archives must resist corruption/wrong passwords/path traversal/link escapes. Online copy cannot be advertised as transactionally consistent; final stopped-writer snapshot is mandatory for retirement. Preview must not send duplicate emails, poll upstream scheduler jobs, advertise duplicate HomeKit identities or join production tunnel. 256 GB target requires a disk estimate and optional models rather than blindly pulling everything. Existing browser profiles can carry Windows absolute paths and locks; preserve originals and explicitly report reauthentication needs. FileVault reboot unlock is an owner configuration/recovery consideration to document. Current device LAN endpoints and Ethernet trusted-network behavior require physical validation.

## Acceptance checks

- Focused runtime tests prove Windows/POSIX path handling, symlink containment and default production vs staging behavior; syntax checks on touched runtime.
- Synthetic export round trip preserves ignored secrets, hidden encryption key, dirty Git files and content; corruption/wrong-key rejection; no symlink traversal; size/checksum reporting; final/preliminary labels; nonsecret inventory.
- bash -n all shell entry points; synthetic Node config/manifest tests; review launchd XML escaping, idempotence and missing dependencies. Windows can validate syntax/helpers, not claim launchd/Xcode/HomeKit physical success.
- Run appropriate existing Node regression suite without touching production state; inspect actual full diff and secret leakage.
- Build a user-ready zip containing only setup tools/instructions and encrypted payload (if practical), recovery key stored separately on Windows. Verify payload locally against manifest. Report exact locations, size and SHA-256.
- Final guide states concrete first run, one-time account/permission steps, preview verification, stopped-writer final export, traffic activation, reboot check, private backup and retirement gate; rollback must address writes after cutover.
